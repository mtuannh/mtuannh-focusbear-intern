## Troubleshooting Coding Problems

When I have a coding problem, I would first try to understand the problem myself instead of immediately asking for help. I would read the error message, check the relevant code and try to reproduce the issue. After that, I would decide whether I should use Google, an AI tool, or ask a colleague based on the situation.

## When do you prefer using AI vs. searching Google?

I prefer using AI when I have a more complicated problem or when I am not sure what approach I should take. AI is useful because I can explain the problem in more detail and ask follow-up questions to understand different possible solutions.

I prefer using Google when I am looking for specific documentation, an error message, or an established solution. For example, if I need to understand how a React or JavaScript feature works, I would usually check the official documentation or search for examples from reliable sources.

I also think it is important not to blindly trust an AI-generated solution. I should understand why the solution works and test it myself before using it in the project.

## How do you decide when to ask a colleague instead?

I would ask a colleague when I have already tried to solve the problem myself and I am still blocked, especially if the problem is related to the project's specific requirements or existing architecture.

I would also ask a colleague when the information is sensitive or when I need to make a decision that could affect the project. In these situations, a team member who understands the project context can usually give more appropriate advice than a general online source or AI tool.

Before asking, I would try to explain what I have already tried and what I think the problem is. This makes it easier for the colleague to understand the situation and help me.

## What challenges do developers face when troubleshooting alone?

One challenge is that it can be easy to spend too much time going in the wrong direction. When working alone, I might make assumptions about the problem that are not correct and keep trying solutions based on those assumptions.

Another challenge is that I may not have enough context about the existing codebase. A problem that looks like a simple coding error could actually be related to how the project is structured or how the team expects a feature to work.

Working alone can also make it harder to know when to stop investigating and ask for help. This is why I think having a clear troubleshooting process is useful. I should try to investigate the problem first, but I should also recognise when asking a colleague would be more efficient.

## My Troubleshooting Strategy

My general approach is:

1. Understand and reproduce the problem.
2. Read the error message carefully.
3. Check the relevant code and recent changes.
4. Search Google or official documentation for specific technical information.
5. Use AI when I need help understanding the problem or exploring possible solutions.
6. Verify and test any solution before using it.
7. Ask a colleague if I am still blocked or if the problem requires project-specific knowledge.
8. Document the solution if it could be useful in the future.

## Reflection

This task helped me understand that there is no single best resource for every coding problem. Google, AI tools and colleagues all have different strengths. AI can be useful for explaining concepts and exploring ideas, Google and official documentation are better for finding specific and reliable technical information, while colleagues are more useful when the problem depends on the project's context.

As an intern, I think it is important to try solving problems independently first, but also to avoid spending too much time stuck on something that could be solved more quickly by asking for help.
